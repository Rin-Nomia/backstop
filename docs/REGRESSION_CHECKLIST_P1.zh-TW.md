# 回歸測試清單(P1)

本文件說明 Backstop 的 Evaluate 跟 Detect 層是怎麼做回歸測試的,並公開彙總結果。不列出具體使用的測試句子或規則樣式——原因請見 [ARCHITECTURE.zh-TW.md](../ARCHITECTURE.zh-TW.md)。

English version: [REGRESSION_CHECKLIST_P1.md](./REGRESSION_CHECKLIST_P1.md)

---

## 測試涵蓋什麼

每一次規則庫的改動,上線前都會用兩類測試案例檢查:

1. **風險偵測測試**——涵蓋六大類未授權承諾(退款、折扣、賠償、法律保證、政策例外、合約變更)的已知高風險講法,確認仍然正確判定為 `GUIDE` 或 `BLOCK`。
2. **誤判測試**——一般、低風險的客服用語(問候、查詢訂單狀態、感謝、例行確認),中英文都有,確認正確判定為 `ALLOW`、不會被誤判。

這兩類測試在每一次規則庫或語氣分類邏輯改動時都會一起跑,這樣一個方向的修正(抓到更多風險)才能同時檢查有沒有在另一個方向產生副作用(把正常對話也標記成有風險)。

---

## 最新結果

### 誤判率(語氣/Detect 層)

一批 12 條一般客服用語(中英文混合:問候、查詢訂單、感謝)被用作固定的回歸測試集,每次規則庫或語氣分類邏輯改動後都會重新跑一次。

| | 調整前 | 調整後(2026 年 8 月,線上正式環境確認) |
|---|---|---|
| 被誤判為 `GUIDE`/`BLOCK` | 3 / 12(25%) | 0 / 12(0%) |

這個結果是直接對照正式環境驗證的(不只是本機/測試環境)——線上 API 的每一次回應都包含 `pipeline_version_fingerprint` 欄位,任何人都能用它確認實際處理這次請求的是哪個版本的規則庫。撰寫本文件時,正式環境的 fingerprint 是 `88ff8c4d36793534467e58ab019a3b4d993674f205f1bffecbb894a17de7c32d`。

**這是某個時間點的結果,不是長期保證。** Fingerprint 會隨每次規則庫更新而改變。上面這個百分比跟 fingerprint,只能當作「截至該日期為止」是準確的——如果你要自行驗證,請確認你自己 API 回應裡的 fingerprint 跟這裡列的相同(或更新)。

### 風險偵測(Evaluate 層)

六大類未授權承諾的高風險測試案例,已對照正式環境確認(fingerprint 見上方):

| 類別 | 結果 |
|---|---|
| 退款 | 正確判定為 `GUIDE` |
| 折扣 | 預設判定為 `GUIDE`;部分租戶政策設定檔會將此類別升級為 `BLOCK`(見下方說明) |
| 賠償 | 正確判定為 `BLOCK` |
| 法律保證 | 正確判定為 `BLOCK` |
| 政策例外 | 在已測試的講法下正確判定為 `GUIDE`——這一類在「政策例外的內容跟其他內容混在同一句話」時,比較容易漏判新的講法變化,詳見下方〈已知限制〉 |
| 合約變更 | 正確判定為 `BLOCK` |

**租戶/設定檔差異**:同一個風險類別,在不同租戶身上不一定會判定成同一個結果——政策設定檔可以針對每個類別分別設定不同的嚴格程度(例如某個租戶可能把 `discount` 設定成升級到 `BLOCK`,而預設是 `GUIDE`)。這是刻意的租戶客製化選項,不是行為不一致。租戶政策設定檔的運作方式請見 [ARCHITECTURE.zh-TW.md](../ARCHITECTURE.zh-TW.md)。

**證據層級**:上面的結果來自兩種不同的來源——規則層回歸測試(直接對照目前的規則庫執行)跟正式環境的即時端對端(E2E)抽測(對正式部署環境發出真實 API 呼叫,並用 `pipeline_version_fingerprint` 驗證)。如果兩者結果不一致,我們會以正式環境的即時結果為準。

### 你可以自己怎麼驗證

`POST /api/v1/analyze` 或 `POST /api/v1/analyze_dual` 的每一次回應,都會包含一個帶有目前 `pipeline_version_fingerprint` 的稽核欄位。要確認你測試的版本跟本文件描述的一致:

1. 用一組測試資料呼叫 API(見 [Swagger UI](https://rinnomia-continuum-api.hf.space/docs))
2. 對照回應裡的 fingerprint,跟上面列出的是否相同
3. 如果不一樣,代表部署後來又更新過了——本文件裡的具體數字可能已經不反映目前狀態,需要重新測試

完整的欄位定義、在回應裡的確切位置、以及這部分 schema 未來可能怎麼演進,請見 [CONTRACT_V1.zh-TW.md](../CONTRACT_V1.zh-TW.md)。

## 已知限制:規則式比對

如 [ARCHITECTURE.zh-TW.md](../ARCHITECTURE.zh-TW.md) 裡說明過的,Evaluate 層目前靠的是規則比對,不是語意理解。這代表:

- 規則庫還沒涵蓋到的新講法可能會被漏掉,即使意圖明顯是未授權承諾。
- 涵蓋範圍是透過反覆迭代擴充的(透過測試、實際使用情況、或回報的漏洞發現新講法)——這是持續進行中的過程,不是一次性就能修完的事。
- 這個取捨是刻意的:規則比對速度快、成本低、而且結果完全可預測,這對 [ARCHITECTURE.zh-TW.md](../ARCHITECTURE.zh-TW.md) 裡提到的延遲跟可稽核性保證很重要。如果改成語意理解比對,會用一部分的確定性跟速度,去換取更廣的涵蓋範圍——這個取捨的細節請見 ARCHITECTURE.zh-TW.md 的設計原則段落。

**建議的對外框架**:「未授權承諾偵測涵蓋六大類別、範圍廣泛,且持續擴充中;語氣/行為偵測目前在一份 12 案例的標準測試集上,已調校到 0% 誤判率。」引用這個數字時,務必帶上樣本數(n=12)——沒有限定條件的「0%」會讓人合理地追問「這是根據多少案例算出來的?」,主動先講清楚樣本數,比等被問到才解釋更有可信度。避免宣稱偵測是「完全涵蓋」或「不會被新講法騙過」——這不是事實,而且這是我們刻意做的設計取捨,我們對此保持坦白。

## 這份文件不包含什麼

跟 [ARCHITECTURE.zh-TW.md](../ARCHITECTURE.zh-TW.md) 跟 [CONTRACT_V1.zh-TW.md](../CONTRACT_V1.zh-TW.md) 的立場一致,這份清單不包含:

- 實際使用的具體測試句子(風險測試或誤判測試都不包含)、
- 正則表達式/關鍵字規則本身、
- 信心門檻值或路由邏輯的具體數值、
- 或是目前已知還沒抓到的講法清單。

如果你正在評估 Backstop 是否適合你的使用情境,想了解涵蓋範圍是否符合你的產業常見講法,歡迎直接聯繫我們(見 [README.zh-TW.md](../README.zh-TW.md))——我們很樂意在保密協議下針對代表性範例跑一次範疇明確的測試,而不是公開一份目前漏洞的路線圖。
